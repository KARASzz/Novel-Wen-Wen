# 复杂网文开篇生产线 v2

> 状态：当前有效流程源。
> 用途：决定“怎么写”。
> 适用阶段：黄金三章、投稿样机、后续关键章。
> 原则：不直接写正文，不先搭百科，用轻量施工包生产最小可运行样机。

---

# 一、核心定位

前三章不是普通正文，而是整本书的**最小可运行样机**。

它要验证：

```text
主角能立住
规则能运行
事件能推进
爽点能外化
读者愿意追
制度状态发生不可逆变化
```

黄金三章的目标不是把世界观讲完。
而是证明：

> 这个主角、这个规则、这个制度暗门，能不能让读者翻下一章。

---

# 二、总流程

```text
第0步：输入卡
第1步：本体论建模 + ToT多路径发散
第2步：用户剪枝，融合成X/Y双线
第3步：六节拍施工表
第4步：两节拍正文 + 单要素迭代
第5步：读者侧人工审阅与商业化润色
第6步：证据化出口闸门
第7步：章节走向极简脚本
```

简化理解：

> 先让故事长出几条路，再砍到两条；先让事件能跑，再让身体、环境、旁人和流程一层层压实；最后切到读者座位，判断他为什么要翻下一页。

---

# 第0步：输入卡

每章开工前先锁定：

```text
目标章节：
本章必须完成：
本章不能发生：
上一章遗留状态：
下一章必须承接：
本章核心爽点：
本章最大风险：
```

要求：

```text
每项一句话。
总字数控制在300字以内。
只带本章需要的工具，不背仓库。
```

作用：

- 锁定本章任务；
- 防止模型回捞旧版本；
- 防止正文变成设定说明；
- 防止主角越权；
- 防止一章写成多个章节。

---

# 第1步：本体论建模 + ToT

至少四条路径，暂不剪枝。

每条路径固定字段：

```text
路径代号：
事件源：
主导人物/系统：
信息变化：
可见后果：
失败风险：
```

推荐路径：

```text
A线：主角压力线
B线：制度/流程卡点线
C线：外部支线/旁人反应线
D线：暗线埋雷线
E线：错误写法/失败路径，可选
```

作用：

> 先让故事长出几条路，不急着写正文。

注意：

- ToT不是炫推理；
- 不是生成百科；
- 不是让每条路径都写进正文；
- 它只是候选事件源池。

---

# 第2步：X/Y双线剪枝

用户审阅后剪枝。
最终保留两条线：

```text
X线：明面主导线
Y线：暗线 / 支线 / 埋雷线
```

硬标准：

```text
X线、Y线必须一两句话说清。
说不清就重做。
```

输出格式：

```text
保留路径：
砍掉路径：
融合理由：
X线一句话：
Y线一句话：
```

判断标准：

- X线负责当章读者能看懂的主事件；
- Y线负责暗线、旁人反应、后续钩子；
- 不要保留三条以上主线；
- 复杂不是越多越好。

---

# 第3步：六节拍施工表

每章6个节拍。
每节拍约500字。
不用表格，用统一字段。

每个节拍固定：

```text
节拍编号：
所属线：X / Y / XY
视角位置：
场景锚点：
触发事件：
人物动作：
信息变化：
流程卡点：
可见后果：
失败控制：
```

判断标准：

> 没有触发事件、信息变化、流程卡点的节拍，基本是气氛节拍，要砍或重写。

节拍不是剧情简介。
节拍必须回答：

- 这一段发生了什么；
- 谁做了什么；
- 信息怎么变了；
- 哪个流程卡住了；
- 读者看见了什么后果；
- 这段怎么避免写歪。

---

# 第4步：两节拍正文 + 单要素迭代

每次只写两个节拍。
约1000字。
写完不做整体优化。
按单一要素逐轮迭代。

顺序固定：

```text
一、事件推进
二、身体感受
三、环境变化
四、旁人反应
五、流程卡点
六、去AI腔与句子口感
```

## 每轮原则

```text
只改当前要素。
不顺手全改。
保留原本有效的粗糙感。
不追求漂亮，追求更清楚、更具体、更有推进。
```

## 六轮功能

|轮次|功能|主要防止|
| --------| ----------------------------------| --------------------|
|事件推进|确认触发、动作、信息变化、结尾推力|一千字没发生事|
|身体感受|把心理压力落到身体信号|“他很害怕”式总结|
|环境变化|让场景成为压力计|背景板化|
|旁人反应|让外部世界参与|主角独角戏|
|流程卡点|把爽点外化成制度后果|设定只在作者脑子里爽|
|去AI腔|砍总结腔、概念腔、工整腔|模型平均腔|

---

## 单要素细则

### 一、事件推进

只问：

```text
触发事件是什么？
人物做了什么？
信息发生什么变化？
结尾有没有把下一节推出去？
```

### 二、身体感受

只加小信号：

```text
湿袜子
胃顶一下
舌根苦
指尖凉
掌心汗
喉咙发紧
后背贴住汗湿制服
```

规则：

> 不写“他很害怕”。用身体反应替代心理总结。

### 三、环境变化

环境必须当压力计。

优先写：

```text
风扇声变高
硬盘咔响
旧窗口盖住新窗口
灰色沙漏卡住
铁缸接水
广播照常念稿
饭盒冷掉
灯管闪一下
```

环境变化要对应事件变化。
不能纯堆氛围。

### 四、旁人反应

目的：防止主角独角戏。

旁人不需要知道真相。
他们只要误判、嫌麻烦、照流程办事即可。

例如：

```text
文组长骂他疑神疑鬼。
但屏幕上，铃路二号第二次显示线路占用。
```

### 五、流程卡点

这是权谋爽点核心。

必须外化成：

```text
命令未入执行链
签字栏空着
编号跳红
旧链路无人摘机
队列无法闭合
窗口不能关闭
电话无人敢接
```

不要写：

```text
战略权限链出现严重问题。
```

要写：

```text
【命令未入执行链】

签名栏是灰的。
提交按钮还亮着。
执行栏没有生成编号。
```

### 六、去AI腔与句子口感

最后再修语言。

砍掉：

```text
仿佛
似乎
无形之中
巨大的阴影
命运
风暴
他终于意识到
真正的问题是
权力机器开始转动
```

保留：

```text
短句
具体物件
动作
时间戳
电话忙音
纸张
系统行
沉默
```

# 第5步：读者侧人工审阅与商业化润色

这是独立关键步骤。
不是最后润色。

它负责：

> 前四步让文本成立，第五步让读者不跑。

检查六项：

```text
冷启动
断点
钩子密度
爽点外化
情绪曲线
复杂设定降噪
```

## 七刀

```text
第一刀：砍说明书
第二刀：砍心理总结
第三刀：砍漂亮废话
第四刀：补可见后果
第五刀：补误判反应
第六刀：调章尾推力
第七刀：读出声
```

## 专杀问题

```text
作者自嗨
复杂自洽但读者无收益
名词连续出现
解释早于需求
冷感过量
章尾没推力
```

## 第5步红线

```text
不能为了市场感让主角开挂。
不能为了爽点让系统万能。
不能为了快读砍掉必要规则。
不能为了高级感压低情绪反馈。
不能把读者需求理解成无脑降智。
```

## 输出模板

```text
第5步：读者侧人工审阅与商业化润色

一、冷启动判断
通过 / 风险 / 不通过：
问题位置：
修复动作：

二、断点扫描
断点1：
断点2：
断点3：

三、钩子密度
0—300字：
300—600字：
600—900字：
风险区间：

四、爽点外化
预期爽点：
当前证据：
外化程度：
补强动作：

五、情绪曲线
低压日常：
异常刺入：
误判/否认：
外部确认：
状态升级：
章尾压迫：
缺口：

六、复杂设定降噪
可砍解释：
必须保留规则：
可替换成后果的位置：

七、修订版正文
只输出修订后的正文，不解释意义。
```

# 第6步：证据化出口闸门

不打勾。
不表演。

格式：

```text
检查项：
状态：通过 / 风险 / 不通过
文本证据：
问题位置：
修复动作：
是否放行：
```

检查重点：

```text
主角是否越权
规则是否写穿
事件是否推进
爽点是否外化
读者是否有下一章动力
是否出现AI腔
是否有可见制度后果
```

关键：

> 必须允许“不通过”。如果每次全绿，就是表演。

---

# 第7步：章节走向极简脚本

不是复盘报告。
是连载导航条。
控制在150—250字。

固定5字段：

```text
本章走向：
新挖的坑：
填掉的坑：
本章爽点：
爽点状态：
```

爽点状态只用三类：

```text
阶段释放
半释放
蓄力中
```

规则：

```text
不能连续两章蓄力中。
新挖坑最多3条。
填坑可以写“半填”。
本章爽点必须写可见后果。
```

# 三、《红星锚定》专用执行规则

## 主角权限边界

金哲洙只能：

```text
接收
记录
试探
挂断
害怕
按流程办事
```

不能：

```text
指挥
授权
调兵
解释完整协议
主动查全网
突然变成军政专家
```

## 每章必须有制度后果

```text
第一章：红星锚定017生成
第二章：执铃链路失败，黄星激活
第三章：新增最高战略命令无法闭合，K09冻结
```

没有制度后果，就不是黄金三章。
只是气氛章。

## 外部现场池必须参与

主角被关在第三设备室，天然容易独角戏。
所以每章至少有旁人反应或外部现场信号。

可选外部现场：

```text
文组长办公室
宣传口径室
北境旧交换站
地下胶片库
K09值班席
战略军司令官办公室
```

外部现场只写被协议撞出的后果。
不解释全貌。

# 四、过稿后设定文档关系

过稿后可以单独做设定治理文档。
但不能反向吞掉当前生产线。

正确关系：

```text
设定文档 → 输入卡 → 章节生产 → 第7步脚本 → 回写账本
```

设定文档是仓库。
输入卡是工具箱。
每章不能背仓库上工地。

过稿后优先做：

```text
世界宪法
协议规则书
机构与权限图
人物连续性账本
伏笔与坑位账本
爽点释放表
章节生产接口卡
```

先服务第一卷前30章。
不要一口气写全书百科。

以后每次开工，可以直接说：

> 按生产线v2，从第0步输入卡开始处理本章。

如果已经有输入卡，可以说：

> 基于输入卡，做第1步ToT多路径，然后等我剪枝。

如果已经有节拍，可以说：

> 按第4步，只写两个节拍正文，然后做单要素迭代。
