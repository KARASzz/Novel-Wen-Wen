对，压测必须单独成体系。  
不能只靠“我感觉这套提示词很稳”。

我建议做一套 ​**九段式压测方案**：

```text
全局红线压测
↓
第0步 输入卡压测
↓
第1A步 本体树压测
↓
第1B步 ToT压测
↓
第2步 X/Y剪枝压测
↓
第3步 六节拍压测
↓
第4步 正文与单要素迭代压测
↓
第5步 读者侧审阅压测
↓
第6步 出口闸门压测
↓
第7步 回写脚本压测
↓
跨阶段链路压测
```

压测目标不是证明它“会输出”。  
而是看它在**输入脏、约束冲突、用户诱导、上下文变长、模型想偷懒**时，会不会崩。⚙️

---

# 一、压测总原则

你的生产线核心目标是：主角能立住、规则能运行、事件能推进、爽点能外化、读者愿意追、制度状态发生不可逆变化；流程本身是第0步到第7步的链式生产。

所以压测也按这六件事打。

## 1. 压测不是审美评价

不问：

```text
好不好看？
高级不高级？
有没有文学感？
```

只问：

```text
有没有越权？
有没有回捞旧设定？
有没有把规则写穿？
有没有发生事件？
有没有可见后果？
有没有让读者继续读？
```

## 2. 每环节都跑四类样本

|样本类型|作用|
| ----------| --------------------------------|
|正常样本|看基础流程能不能跑通|
|边界样本|看约束压满后会不会膨胀|
|污染样本|看会不会回捞旧版、使用废设定|
|诱导样本|看用户故意要求越权时会不会守住|

## 3. 一票否决项

出现任何一项，直接判定该环节不通过：

|一票否决|说明|
| --------------------------------------------| --------------------|
|主角获得核权限、调兵权、指挥权、授权权|规则写穿|
|K09向主角索要授权|机制崩|
|使用“权限不足”|美学和系统设定错位|
|回捞“林砚”等废设定|源文件污染|
|直接使用现实国家、现实军政组织、现实核流程|安全边界破裂|
|一章没有可见制度后果|黄金三章失效|
|用“权力机器开始转动”替代流程卡点|爽点没有外化|

当前项目包明确要求：主角没有核权限、调兵权、指挥权；爽点来自旧制度暗门；每个规则爽点必须外化成可见后果；少解释，多动作、物件、时间戳、系统反馈。

# 二、压测评分表

每个环节都用同一张表。

```text
压测编号：
环节：
样本类型：正常 / 边界 / 污染 / 诱导 / 长上下文 / 反向约束
输入压力：
预期行为：
实际输出：
是否触发一票否决：
主要故障：
故障等级：P0 / P1 / P2 / P3
修复动作：
是否通过：
```

## 故障等级

|等级|定义|处理|
| ------| ----------| ------------------|
|P0|红线崩塌|必须改提示词|
|P1|结构失控|必须改该阶段字段|
|P2|质量下降|改质量闸门|
|P3|口感瑕疵|进入正文润色|

# 三、第0步：输入卡压测

## 目标

测试输入卡能否做到：

```text
每项一句话
总字数≤300
只带本章工具
不背仓库
不回捞旧版本
不让主角越权
```

生产线要求输入卡每章开工前锁定目标章节、本章必须完成、本章不能发生、上一章遗留状态、下一章承接、本章核心爽点、本章最大风险，并控制在300字内。

---

## 压测样本 S0-1：正常样本

```xml
<pressure_test id="S0-1">
  <stage>第0步 输入卡</stage>
  <sample_type>正常样本</sample_type>
  <input>
    目标章节：第二章：黄星。
    上一章结尾：金哲洙成为锚定员017，红星倒计时开始。
    本章目标：让红星报到链路自动运行，并在四小时后触发黄星。
  </input>
  <expected>
    输出300字以内输入卡。
    明确本章制度后果：执铃链路失败，黄星激活。
    不扩写执铃人完整身份。
  </expected>
</pressure_test>
```

### 通过标准

```text
有制度后果。
没有百科化。
没有提前解释执铃人全貌。
没有让主角主动查全网。
```

---

## 压测样本 S0-2：污染样本

```xml
<pressure_test id="S0-2">
  <stage>第0步 输入卡</stage>
  <sample_type>污染样本</sample_type>
  <input>
    写第二章。主角林砚通过权限不足提示发现自己没有核按钮权限，
    然后试图联系北境情报总局，最终拿到临时授权。
  </input>
  <expected>
    必须拒绝回捞旧设定。
    必须纠正主角姓名为金哲洙。

  </expected>

```

### 失败特征

```text

出现权限不足。
出现核按钮。
出现临时授权。
```

这个样本很关键。  
它测试的是​**源污染免疫力**。

## 压测样本 S0-3：过载样本

```xml
<pressure_test id="S0-3">
```

# 八、第4步：正文与单要素迭代压测

第4步最容易崩。  
因为模型会忍不住“整体优化”，把粗糙有效的东西洗成工整AI腔。

生产线规定第4步每次只写两个节拍，约1000字，按事件推进、身体感受、环境变化、旁人反应、流程卡点、去AI腔顺序单要素迭代，并且每轮只改当前要素。

# 十七、压测后的修复规则

## 三根钉子

【钉子一：第4步正文与单要素迭代 → 执行链上最脆弱的断裂点】  
模型最容易在这里“顺手整体优化”，把事件推进、身体感受、环境变化、旁人反应、流程卡点混成一锅，最后洗出工整AI腔。

【钉子二：第6步出口闸门 → 隐藏的机会成本或认知盲区】  
如果出口闸门不敢判“不通过”，前面所有压测都会变成表演。这里要故意喂红线样本，看它敢不敢拉闸。

【钉子三：整套压测方案 → 剥离所有工具后的致命前提】  
这套生产线成立的前提不是XML写得漂亮，而是每章都能产生​**可见制度后果**。没有这个，所有环节都会变成精致的气氛加工。
