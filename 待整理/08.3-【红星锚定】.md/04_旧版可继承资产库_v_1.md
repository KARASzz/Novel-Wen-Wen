# 04_旧版可继承资产库 v1

> 状态：归档型有效辅助源。
> 用途：从旧版提示词、旧版小说资料库、旧版写作系统中提取可继承资产，作为当前生产线的插件库。
> 优先级：低于当前项目包、当前生产线、美学基座、增量补丁。
> 使用原则：只取插件，不复活旧系统；只进入章节生产接口，不整包投喂正文。

---

## 0. 总原则

当前正式生产线只认：

```text
输入卡 → ToT多路径 → X/Y双线剪枝 → 六节拍施工表 → 两节拍正文 → 单要素迭代 → 读者侧审阅 → 出口闸门 → 极简脚本回写
```

旧版资产的功能不是替代这条生产线。

它只负责补四类东西：

```text
规则更清楚
人物不飘
读者不超载
连续性不崩
```

凡是不能服务这四件事的旧资产，默认归档。

## 2. 规则卡

### 2.1 功能

用于防止高概念设定写穿。

适合处理：

```text
协议
系统
科技
能力
机构
权限
战略流程
神秘规则
```

### 2.2 放入生产线位置

```text
第0步：输入卡
第3步：六节拍施工表
第6步：证据化出口闸门
```

### 2.3 标准模板

```text
规则名：

能做：

不能做：

触发条件：

权限边界：

知情范围：

失败条件：

误触发路径：

被利用路径：

本章可见后果：

本章禁止写法：
```

### 2.4 使用规则

规则卡只写本章需要的部分。

不要把完整设定搬进输入卡。

输入卡最多放2条规则。

如果超过2条，说明本章设定负荷过高，需要拆章。

### 2.5 判断标准

一条规则是否能进入正文，必须回答：

```text
它让谁不能做什么？
它让哪个流程卡住？
它让读者看见什么后果？
```

答不上来，先不进正文。

## 3. 认知可达性标注

### 3.1 功能

用于判断一个设定本章该不该解释、怎么解释、解释到什么程度。

### 3.2 四级分类

|等级|定义|正文处理|
| ------| ------------------| ------------------|
|直觉级|读者一看就懂|直接使用|
|解释级|一两句能懂|用一句边界说明|
|建构级|需要场景演示|必须让设定撞出事件|
|过载级|本章解释会拖垮节奏|推迟|

### 3.3 输入卡格式

```text
本章新概念：
1. 【概念名】等级：直觉级 / 解释级 / 建构级 / 过载级
   处理方式：

2. 【概念名】等级：直觉级 / 解释级 / 建构级 / 过载级
   处理方式：
```

### 3.4 硬规则

```text
每章新概念最多2个。
建构级概念最多1个。
过载级概念禁止进入正文。
```

### 3.5 错误示例

```text
本章解释红星、黄星、K09、执铃人、继承集团、战略命令链、旧交换站。
```

问题：新概念爆炸。

### 3.6 正确示例

```text
本章新概念：
1. 黄星协议【建构级】
   处理方式：不解释全貌，只写新增命令未入执行链。

2. Y-17故障码【解释级】
   处理方式：先显示故障码，再由老技师说一句“Y类不是设备故障”。
```

## 4. 角色三字段审计

### 4.1 来源

旧版L2b自由能角色档案、L3行为模式库、L6语言层。

当前不继承完整L1-L6。

只继承三字段。

### 4.2 标准模板

```text
人物：

顽固预测：
他无论遇到什么证据，都会优先相信什么？

默认动作：
这个信念被触发后，他第一反应会做什么？

崩溃阈值：
什么事件会让他的旧反应不够用了？
```

### 4.3 放入生产线位置

```text
第0步：输入卡
第3步：六节拍施工表
第4步：正文写作前的动作约束
第6步：人物越界检查
```

### 4.4 使用规则

每章最多放2个人物三字段。

普通功能性配角不建完整档案。

只写本章会被触发的动作。

### 4.5 金哲洙示例

```text
人物：金哲洙

顽固预测：
多做一步，就会背锅。

默认动作：
看时间戳，查流程，试探上级，不主动解释，不越权。
压力过大时先切断接触。

崩溃阈值：
当所有上级都在借死人继续发命令，而真实死亡时间只有他能保存时，
“这事轮不到我”不再够用。
```

### 4.6 判断标准

如果正文里角色行为和三字段冲突，必须满足至少一条：

```text
他已经被逼到崩溃阈值。
他获得了新的信息。
他付出了明确代价。
他不是成长，而是误判。
```

否则就是作者硬推。

## 5. 黄金样本

### 5.1 功能

黄金样本不是剧情模板。

它只提供：

```text

感官比例
```


### 5.3 禁止用法

```text

复制宏大意象
复制人物表达
复制章节结构
复制术语密度
```

### 5.4 标准调用格式

```text
本章口感锚点：
参考样本：
只继承：
禁止继承：
```

## 7. 惊异预算

### 7.1 原资产问题

旧版惊异预算完整区分：

```text
事件惊异
角色惊异
设定惊异
叙事惊异
```

有价值，但日常使用太重。

### 7.2 当前降级版本

每章只问一句：

```text
本章主惊异是什么？
事件 / 角色 / 设定 / 叙事，只选一个。
```

### 7.3 模板

```text
本章主惊异：事件 / 角色 / 设定 / 叙事

读者原本以为：

实际发生：

惊异落点：

模型更新窗口：第几节拍让读者消化？

不能同时拉满的东西：
```

### 7.4 判断标准

一章最多一个高惊异。

如果同一章同时出现：

```text
新设定
新人名
新组织
新能力
新地图
大反转
大情绪
```

读者不是震撼，是疲劳。

---

## 8. 模型更新窗口

### 8.1 功能

高惊异之后，读者需要一个短暂消化段。

这个段落不是解释百科。

它是让读者看到：

```text
人物怎么反应
系统怎么变化
旁人怎么误判
流程怎么卡住
```

### 8.2 放入六节拍施工表

```text
节拍编号：
是否为模型更新窗口：是 / 否
消化内容：人物反应 / 系统后果 / 旁人误判 / 流程卡点
```

### 8.3 错误示例

高惊异后立刻塞第二个高惊异。

```text
红星刚出现，马上解释黄星、K09、执铃人、继承派系、旧统帅部。
```

### 8.4 正确示例

```text
红星出现后，不解释全貌。
让金哲洙先看新闻。
新闻里最高领袖仍在明日视察。
屏幕上倒计时继续减少。
```

## 9. 四Agent治理压缩版

### 9.1 原资产问题

四Agent完整协作适合重点章、卷末章、系统审计。

不适合每章日常生产。

### 9.2 当前压缩为三问

```text
守卫问：
规则有没有被写穿？

审计问：
人物行为是否越过知情范围、权限边界和动机边界？

代言人问：
读者在这一章看见了什么新后果？
```

### 9.3 放入第6步出口闸门

```text
检查项：守卫问
状态：通过 / 风险 / 不通过
文本证据：
问题位置：
修复动作：

检查项：审计问
状态：通过 / 风险 / 不通过
文本证据：
问题位置：
修复动作：

检查项：代言人问
状态：通过 / 风险 / 不通过
文本证据：
问题位置：
修复动作：
```

### 9.4 不通过规则

必须允许不通过。

如果每章全通过，就是表演。

## 10. SHAP / LIME降级为最大负因子

### 10.1 原资产问题

SHAP / LIME术语过重。

但“定位最大问题，只改一个主因”的方法有价值。

### 10.2 当前模板

```text
最大负因子：

如果只改一个地方：

问题根因：
事件不足 / 身体不足 / 环境不足 / 旁人不足 / 流程不足 / 语言腔调不足 / 读者回报不足

扰动测试：
1. 删掉这段会不会更好？
2. 缩短一半会不会更好？
3. 换成旁人反应会不会更好？
4. 把心理总结换成动作会不会更好？
5. 把解释换成系统反馈会不会更好？

最小修改方案：
```

### 10.3 放入生产线位置

```text
第5步：读者侧人工审阅与商业化润色
```

不要在正文初稿前使用。

初稿前用它，会把写作变成审稿。

## 12. 受控失控协议

### 12.1 是否继承

继承，但不在黄金三章使用。

### 12.2 使用时机

```text
第一卷30章后
连续三章执行过稳
人物互动产生更好的自然走向
原大纲开始压制角色生命力
```

### 12.3 当前模板

```text
受控偏离记录：

原计划：

实际偏离：

偏离来源：角色动作 / 关系变化 / 场景压力 / 规则后果

是否更好：是 / 否 / 待观察

代价：

是否回写大纲：
```

### 12.4 禁止

不能把“我没想好”包装成受控失控。

偏离必须来自正文里已经发生的压力。

## 14. 完整四Agent报告

禁止日常使用。

问题：

```text
报告压过正文
每章都像项目评审
模型会为了填表而制造废话
```

可替代为：

```text
守卫 / 审计 / 代言人三问
```

---

## 15. 完整航行日志

禁止日常使用。

问题：

```text
字段过多
回写成本过高
容易写成漂亮复盘
不能直接指导下一章
```

可替代为：

```text
第7步章节走向极简脚本
```

---

## 16. 完整十阶段流水线

禁止复活为主流程。

问题：

```text
太像大型项目管理
适合资料库搭建
不适合黄金三章冷启动
```

当前主流程已经足够：

```text
第0步到第7步
```

旧十阶段只作为资料来源，不作为操作系统。

---

## 17. 复杂术语自证体系

以下内容不进入当前项目正文生产：

```text
模拟温度值
KL散度
胜率预估
检测风险
AI味消除三人组
过度SHAP化
过度LIME化
高维术语堆叠式审稿
```

理由：

```text
不能直接让章节更好。
不能直接让读者翻页。
不能直接修复人物、规则、事件、流程后果。
```

# 第七部分：红线

---

## 26. 旧版资产使用红线

1. 不整包投喂。
2. 不让审计压过正文。
3. 不让概念压过事件。
4. 不让主角靠作者解释变强。
5. 不用复杂术语替代具体修法。
6. 不为填表制造废话。
7. 不把“系统很完整”当成“章节好看”。
8. 不把黄金样本当句式模板。
9. 不让伏笔账本吞掉章尾钩子。
10. 不用受控失控掩盖大纲失控。

## 27. 判断旧资产是否可用的三问

```text
它是否让本章多发生了一个事件？

它是否让人物动作更符合身份和恐惧？

它是否让读者看见一个可见后果？
```

三问有两个答不上来，归档。

本文件只记录可复用方法，不记录单章剧情。

## 29. 下一步建议

本资产库建立后，建议后续源文件关系固定为：


