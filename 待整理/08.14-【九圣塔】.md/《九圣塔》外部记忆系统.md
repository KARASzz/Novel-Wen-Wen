## Layer 0：核心锚点（固化加载）

```markdown
# 《九圣塔》核心锚点

## 世界观骨架
- **一句话**：九座圣塔以"绝对公平"为名运行社会，实则是九个被制度封装的人类偏执在决定谁有资格被服务
- **铁律**：圣塔不控体——不碰肌肉，只卡流程
- **删除**：剪断主体字段与关系字段，肉身活着但社会性死亡
- **窗口期**：预清洗（28天周期/6小时）+ 慢波（7天周期/9分钟）
- **终局机制**：共振日（预清洗+慢波重叠）执行相位插针

## 处置梯度
G1灰化（毛玻璃）→ G2静音（话入棉花）→ G3断供（门不开）→ G4抹名（目光滑过）→ G5重写（无事发生）

## 三线定义
- **A线**：许行舟取证自救（钥匙收集）
- **B线**：TAC内部派系斗争（强硬派/温和派/黑市派）
- **C线**：地下记忆网络（BEX+总谱节点+童谣传播）

## 主角锚点
- **许行舟**：城建维护员，被删除成"空行"
- **核心缺陷**：相信规则可绕过但不能改变
- **弧线**：绕行者 → 改写者（成为"疤编号"）
- **道具**：发黄旧疫苗腕带（唯一自体底稿）

## 当前进度
- **卷**：[填写]
- **章**：[填写]
- **Day**：[填写]/63
- **DI**：[填写]
- **已获钥匙**：[填写]
```

## 更新协议

### 每次写作会话结束时

```markdown
## 会话结束检查清单

1. **新设定同步**
   - [ ] 本次会话建立了哪些新设定？
   - [ ] 更新「已建立设定清单.md」

2. **伏笔同步**
   - [ ] 本次埋设了哪些伏笔？
   - [ ] 本次回收了哪些伏笔？
   - [ ] 更新「伏笔追踪表.md」

3. **进度同步**
   - [ ] 更新 Layer 0 的「当前进度」
   - [ ] 更新 Layer 1 的「在场人物状态」
   - [ ] 更新 Layer 1 的「读者认知状态」

4. **内容归档**
   - [ ] 场景卡存入对应目录
   - [ ] 正文存入对应目录
```

### 快速同步指令

在会话结束前发送：

```
请输出本次会话的同步清单：
1. 新建立的设定（格式：ID | 内容 | 位置 | 约束）
2. 新埋设的伏笔（格式：ID | 内容 | 位置 | 计划回收卷）
3. 已回收的伏笔（格式：ID）
4. 人物状态变化
5. 读者认知变化
```

## 开新会话的加载流程

```
步骤1：加载系统提示词
       → 核心层 + 所需扩展模块

步骤2：加载 Layer 0（核心锚点）
       → 粘贴完整内容

步骤3：加载 Layer 1（当前作战区）
       → 粘贴当前卷的作战区文档

步骤4：声明任务
       → "今天写第X卷第Y章，场景是Z"

步骤5：按需加载 Layer 2
       → 如涉及特定设定，粘贴相关条目
```

---

**后坐力**：

这个记忆系统解决了"AI不记得上次会话"的问题，但引入了**维护成本**——每次会话结束都要同步，漏一次就会产生设定漂移。

更深层的问题：当你写到卷5，「已建立设定清单」可能有100+条目，Layer 0+1 的 token 会膨胀到 1500+，开始挤压正文生成的上下文空间。

**你需要一个"设定压缩"策略**：哪些设定可以从"显式加载"降级为"按需查阅"？判断标准是什么？
