# 如何利用AI进行长篇小说创作

这是一个非常宏大且专业的问题。作为身兼**架构师、网文作家、AI训练师、算法专家和文学编辑**这五重身份的复合体，我将从系统工程、算法原理、文学创作和实际操作四个维度，为你深度拆解如何利用AI进行长篇小说创作。

---

### 第一部分：架构师视角——小说创作的“模块化拆解”

AI（特别是LLM，大语言模型）本质上是一个概率预测机器，它的**上下文窗口（Context Window）** 和**注意力机制（Attention Mechanism）** 是有限的。如果你试图让它“一次性写完一部小说”或者“写好一个极度复杂的章节”，它的表现会迅速崩塌（逻辑混乱、文风飘忽、产生幻觉）。

因此，必须通过 **“降维打击”** 和 **“模块化”** 来解决复杂任务。我们将小说创作拆解为以下金字塔结构：

#### 1. 顶层设计（World & Concept）

- **任务：**  确立世界观、核心梗（Hook）、力量体系、地图、阵营。
- **AI用法：**  头脑风暴、设定补全。
- **拆解技巧：**  不要让AI一次生成所有设定。
  - *Prompt示例：*  “先帮我设计一个基于‘赛博朋克+修仙’的世界观背景，仅关注社会阶层和能量来源。”

#### 2. 骨架搭建（Structure & Outline）

- **任务：**  总体大纲 -> 卷纲 -> 章纲 -> 细纲（Beat Sheet）。
- **关键点：**  **细纲是AI写作的生命线。**  AI写不好正文，90%是因为细纲不够细。
- **拆解技巧：**  将一章（3000字）拆解为4-6个场景（Scene），每个场景包含：出场人物、核心冲突、情感转折、感官细节提示。

#### 3. 角色工程（Character Engineering）

- **任务：**  建立“角色卡（Character Card）”。
- **内容：**  姓名、外貌、口癖、核心欲望、恐惧、性格关键词（MBTI）、人际关系网。
- **算法逻辑：**  角色卡是AI生成对话和行为时的“系统提示词（System Prompt）”核心来源。

#### 4. 填充血肉（Drafting）

- **任务：**  依据细纲撰写正文。
- **拆解技巧：**  逐个场景生成，而不是整章生成。

#### 5. 润色与质检（Editing）

- **任务：**  风格统一、去除AI味（如滥用的连接词）、逻辑修复。

### 第二部分：AI训练师视角——提示词（Prompt）的高阶技巧

普通的提示词是“请帮我写...”，高手的提示词是 **“代码化的指令”** 。以下是几个核心技巧：

#### 1. 结构化提示词（Structured Prompting）

不要用自然语言写一大段话，要用**Markdown**或**JSON**格式，让AI清晰识别指令边界。

> **模板示例：**
>
> ```markdown
> # Role
> 你是白金级玄幻小说家，擅长《诡秘之主》风格的描写。
>
> # Context
> 当前情节：主角林恩在废弃教堂发现了古神的雕像。
>
> # Task
> 描写林恩走进教堂的心理活动和环境氛围。
>
> # Constraints (约束条件)
> 1. 禁止使用“在这期间”、“总而言之”等AI常用词。
> 2. 多用视觉和嗅觉描写（腐烂的木头味、彩色玻璃的破碎感）。
> 3. 心理活动要体现出san值狂掉的疯狂感，不要太理智。
> 4. 字数：500字左右。
> ```

#### 2. 思维链（Chain of Thought, CoT）

在让AI写正文前，先让它 **“思考”** 。

- *技巧：*  “在开始写作前，请先分析这个场景中主角的情绪变化曲线，并列出3个关键的感官细节。”
- *原理：*  这能激活模型更深层的推理能力，提高逻辑连贯性。

#### 3. 样本学习（Few-Shot Prompting）

给AI“喂”范文。

- *技巧：*  如果你想要古龙风，不要只说“古龙风”，要贴一段古龙的文字，并标注：“请模仿以下文风进行创作：[范文内容]”。
- *原理：*  利用In-Context Learning（上下文学习）调整模型的分布，使其向特定风格靠拢。

#### 4. 负向提示（Negative Prompting）

明确告诉AI**不要**做什么。

- *示例：*  “不要出现心理独白超过3句”、“不要让反派强行降智”、“对话不要像翻译腔”。

### 第三部分：网文作家与编辑视角——一次性生成 vs 分步生成？

**结论：绝对、必须、一定要分开使用。**

 **“一次性生成”是死路，**  原因如下：

1. **注意力稀释：**  输入越长，AI对尾部指令的遗忘率越高。
2. **不可控：**  一次生成3000字，中间写偏了，后面全是废话，修改成本极高。
3. **精度丢失：**  AI倾向于概括叙述（Tell），而不是细节展示（Show）。

**最佳实践流程（流水线作业）：**

1. **Step 1（生成细纲）：**  投喂故事背景 + 简要情节 -> 生成包含4个场景的详细细纲（含对话重点、动作指令）。
2. **Step 2（人工微调）：**   **（关键步骤）**  人工修改细纲，修正逻辑漏洞，增加伏笔。AI的逻辑通常不如人类严密，这一步不能省。
3. **Step 3（场景生成）：**
   - Prompt 1: "根据细纲的场景1，撰写正文。" -> 得到500字。
   - Prompt 2: "根据场景1的内容和细纲的场景2，继续撰写。" -> 得到500字。
4. **Step 4（润色）：**  将生成的片段拼接，统一修改。

### 第四部分：算法专家视角——如何确保“前后一致性”？

这是目前AI写长篇最大的痛点（遗忘设定、性格漂移）。解决这个问题的核心是 **“上下文管理”** 。

#### 1. 建立“动态知识库” (Context Block)

你需要在每次对话的开头，都挂载一个**精简版的“系统记忆区”** 。这就像是给AI外挂了一个RAM。

**每次生成正文时的Prompt结构建议：**

> **[系统记忆区]**
>
> - **世界观：**  赛博修仙，灵气是核辐射。
> - **主角状态：**  林恩（筑基期，左臂机械化，性格冷漠唯利是图）。
> - **当前队友：**  苏苏（AI仿生人，忠诚）。
> - **核心物品：**  只有一把高频振动剑。
> - **上一段剧情摘要：**  林恩刚杀死了帮派头目，现在正躲在下水道里。
>
>  **[当前任务]**   
> 根据以上信息，撰写林恩包扎伤口的场景...

#### 2. 滑动窗口法（Sliding Window Summary）

AI记不住前文的10万字。每写完一章，强制要求AI生成一个**200字的“本章摘要”** 。  
在写下一章时，只投喂： **“全书核心设定 + 上一章摘要 + 当前章细纲”。**

#### 3. 风格锚定（Style Anchoring）

如果发现写着写着文风变了，可以在Prompt中加入固定的**Style Token**（风格指令块）。

- 例如：每次Prompt都包含“保持海明威式的极简主义，多用短句，少形容词”。

#### 4. 自动化检查（Post-Processing）

可以让另一个AI实例充当“编辑”。

- *Prompt：*  “请检查以下文本是否与[角色卡]中的设定冲突？主角是否做出了不符合‘冷漠’性格的行为？如果有，请指出。”

---

### 总结：操作SOP（标准作业程序）

如果你想写好小说，请遵循这个 **“人机协作工作流”** ：

1. **人工+AI：**  确立核心梗和世界观（建立数据库）。
2. **人工+AI：**  规划全书大纲和卷纲。
3. **人工：**  确定本章核心冲突（这是灵魂，必须人定）。
4. **AI：**  将核心冲突扩写为**场景细纲**。
5. **人工：**  修正细纲。
6. **AI：**  **逐个场景**撰写正文（携带[系统记忆区]）。
7. **人工：**  拼接、润色、注入灵魂（金句、潜台词）。
8. **AI：**  总结本章摘要，存入数据库，为下一章做准备。

**核心心法：**  把AI当作一个**执行力超强但记性不好、且容易跑题的实习生**。你（人类）必须是那个掌握方向盘、分发具体任务单、并最后签字验收的**主编**。
