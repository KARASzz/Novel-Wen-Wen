# AI辅助长篇小说创作的全流程

这是一个非常宏大且专业的问题。作为集架构师、网文大神、AI算法专家及文学编辑于一身的角色，我将从**系统工程、算法原理、文学创作论**三个维度，为您深度拆解“AI辅助长篇小说创作”的全流程。

写长篇小说（20万字以上）与写短篇故事对AI来说是两种完全不同的任务。短篇靠灵感，长篇靠**架构**和**记忆管理**。

---

### 第一部分：如何拆解复杂任务（架构师视角）

AI（特别是大语言模型LLM）的底层逻辑是“基于概率的下一个词预测”，它的弱点是**长逻辑推理**和**超长记忆**。因此，架构师必须将“写一本小说”这个模糊的巨型任务，拆解为AI能够理解并执行的“模块化任务”。

我们将任务层级划分为：**世界观层 -> 大纲层 -> 章节层 -> 场景层**。

#### 1. 世界观层（静态数据库）

不要直接让AI写故事，先让它生成“设定集”。

- **拆解动作：**  定义力量体系、地理环境、核心冲突、社会规则。
- **产出物：**  “世界观圣经（World Bible）”。

#### 2. 角色层（动态变量）

- **拆解动作：**  为每个主要角色建立详细的Profile（档案）。包括：姓名、外貌、性格关键词（MBTI）、说话风格（口癖）、核心欲望、恐惧之物。
- **提示词技巧：**  这里的Prompt需要包含**Few-Shot（少样本学习）** ，给AI几段该角色说话的例子，锁定语气。

#### 3. 大纲层（逻辑骨架）

- **拆解动作：**
  - **总纲：**  一句话梗概 -> 三幕式结构。
  - **卷纲：**  每卷的主要事件。
  - **章纲（细纲）：**  这是最关键的一步。不要让AI直接写正文，先让它生成“分场大纲”。
  - *示例：*  “请为第十章生成细纲，包含三个场景，每个场景需要明确：出场人物、冲突点、伏笔、结尾钩子。”

#### 4. 场景层（执行单元）

- **拆解动作：**  这是实际生成的层级。将“章纲”中的一个场景（约1000-1500字）作为一个独立的任务发送给AI。

### 第二部分：提示词（Prompt）使用技巧（AI训练师视角）

优秀的Prompt不是简单的问答，而是**编程**。遵循 **结构化提示词（Structured Prompting）**  逻辑。

#### 1. 核心公式：CRISPE 框架

- **Capacity (角色)：**  定义AI的身份（如：暗黑风网文大神）。
- **Role (背景)：**  提供当前剧情的上下文摘要。
- **Insight (洞察/风格)：**  具体的写作要求（如：多用感官描写，少用形容词）。
- **Statement (任务)：**  具体要写什么（如：写主角进入酒馆的场景）。
- **Personality (语气)：**  文本的情感基调（如：压抑、戏谑）。
- **Experiment (限制)：**  只有对话或全景描写，字数限制等。

#### 2. 高级技巧

- **思维链（Chain of Thought, CoT）：**
  - *错误示范：*  “写一个主角打败反派的场景。”
  - *正确示范：*  “请分步思考：1.分析反派的弱点；2.设计主角发现弱点的契机；3.规划战斗流程；4.基于以上思考，撰写正文。”
- **风格迁移（Style Transfer）：**
  - 不要只说“像古龙一样写”。
  - 要把古龙的文字片段粘贴进去作为参考（Reference），告诉AI：“学习以下文本的断句节奏和用词风格，描写接下来的场景。”
- **负向提示（Negative Prompting）：**
  - 明确告诉AI不要做什么。例如：“不要进行道德说教，不要使用翻译腔，不要让配角像NPC一样只会附和。”

### 第三部分：一次性生成 vs 分开使用（算法专家视角）

**结论：绝对要分开使用（Iterative Generation）。**

#### 原理分析：

1. **上下文窗口（Context Window）限制：**  虽然现在的模型支持128k甚至更长，但**注意力机制（Attention Mechanism）**  会衰减。如果你一次性给太多指令和太长的上文，AI会发生“迷失中间（Lost in the Middle）”现象，导致逻辑崩坏或忽略细节。
2. **幻觉率（Hallucination）：**  任务越复杂，AI胡编乱造的概率越高。
3. **不可控性：**  一次生成3000字，中间写歪了，你后面全是废品。

#### 最佳实践流程（流水线作业）：

1. **Step 1 (生成细纲)：**  输入前情摘要 + 本章目标 -> 输出 3个场景的细纲。
   - *人工介入：*  修改细纲，确保逻辑没问题。
2. **Step 2 (撰写场景A)：**  输入 角色卡 + 场景A细纲 + 风格要求 -> 输出 场景A正文。
   - *人工介入：*  微调，校对。
3. **Step 3 (撰写场景B)：**  输入 场景A的结尾（作为上文） + 场景B细纲 -> 输出 场景B正文。

**只有将任务“切片”，才能保证高质量的颗粒度。**

### 第四部分：如何确保前后一致性（文学编辑视角）

这是AI写长篇最大的痛点（人物性格漂移、死人复活、设定冲突）。解决之道在于**RAG（检索增强生成）思想的手动实现**。

#### 1. 建立动态“记忆库” (The Memory Bank)

你需要维护一个随剧情更新的文档，每次生成时，提取相关部分喂给AI。

- **System Prompt（系统级提示词）：**  始终包含核心设定（主角名、核心性格、世界铁律）。
- **短期记忆（滑动窗口）：**  在Prompt中始终包含**上一章的最后500-800字**，确保剧情衔接顺滑。
- **中期记忆（剧情摘要）：**  每写完一章，让AI生成一个200字的“本章摘要”。写第十章时，把前九章的摘要喂给它。

#### 2. 状态追踪变量

在Prompt的开头，显式定义当前状态：

```markdown
[当前状态]
时间：深夜
地点：废弃医院
在场人物：主角（受伤），反派A
持有物品：生锈的手术刀
主角当前情绪：极度恐慌但保持理智
```

这种“状态栏”能强制AI对齐当前的物理事实，防止出现上一段主角腿断了，下一段就开始跑酷的情况。

#### 3. 后期一致性检查（AI编辑）

写完一章后，开启一个新的AI对话窗口，扮演“苛刻的编辑”。

- **Prompt：**  “这是我刚写的章节（附文本），这是我的人物小传（附设定）。请检查文中角色的行为是否符合其性格设定？是否有逻辑漏洞？不需要修改，只要列出问题。”

### 总结：实战操作模板

如果您现在要开始写，请复制以下工作流：

**阶段一：准备**

1. 用AI头脑风暴，确定核心梗和世界观。
2. 制作详细的人物卡和世界观文档（本地保存）。

**阶段二：规划**

1. 让AI生成全书大纲（修正）。
2. 让AI生成卷纲（修正）。

**阶段三：执行（循环）**

1. **Prompt 1:**  输入当前剧情进度，要求生成**本章细纲**。
   -  *(人工修改细纲)*
2. **Prompt 2:**
   - **Role:**  你是悬疑小说家。
   - **Context:**  (粘贴前情摘要 + 上一章结尾500字)。
   - **Setting:**  (粘贴本场相关的人物卡 + 状态栏)。
   - **Task:**  根据细纲中的场景1进行扩写。
   - **Style:**  沉浸式描写，多用短句。
3. **Prompt 3:**  针对生成的场景1进行润色或重写（如果满意，存入正文文档，更新摘要）。
4. 重复步骤2-3，直到本章结束。

**核心心法：**  AI不是枪手，它是你的**无限算力扩展**。你是导演，它是演员和布景师。不要指望一键生成神作，**分层拆解**和**严格的上下文管理**才是质量的保证。
