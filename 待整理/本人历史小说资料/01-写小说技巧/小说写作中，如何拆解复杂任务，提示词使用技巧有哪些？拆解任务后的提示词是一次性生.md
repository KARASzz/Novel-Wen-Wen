# 小说写作中，如何拆解复杂任务，提示词使用技巧有哪些？拆解任务后的提示词是一次性生成还是分开使用更好？如何确保前后一致性？

我们将小说创作这个宏大的工程，类比为开发一个复杂的软件系统。人类作者是**架构师 (Architect)**  和 **项目总监 (Project Director)** ，而AI大模型则是能力极强但需要明确指令的**程序员/画师 (Programmer/Artist)** 。

---

### 第一部分：深度拆解复杂任务——架构师的“分而治之”

忘掉让AI“写一部小说”这种天真的想法。这就像对一个程序员说“开发一个操作系统”一样，你只会得到一个充满“Hello World”的混乱“玩具”。正确的做法是 **“分而治之” (Divide and Conquer)** 。

我们将一部小说从宏观到微观，拆解为四个核心层级：

**层级一：世界观与设定 (The "God" Layer / The World Bible)**   
这是小说的“底层架构”和“全局配置文件”。在动笔之前，必须由你——架构师——来定义。AI可以作为你的“研究员”和“灵感碰撞器”来辅助你完成。

- **核心任务拆解：**
  1. **世界观设定：**  时代背景、地理环境、物理/魔法法则、科技水平。
     - *子任务示例：*  设计一个名为“源能”的魔法系统，包含其来源、等级划分、施法代价和限制。
  2. **核心概念设定：**  核心冲突（如阶级、种族、神明之战）、社会结构、文化风俗、组织派系。
     - *子任务示例：*  创造一个名为“拜火教”的宗教，描述其教义、仪式、组织架构和在社会中的影响力。
  3. **角色设定 (Character Sheets)：**  主要角色、次要角色的详尽档案。
     - *子任务示例：*  为主角“艾拉”创建一份角色档案，包括外貌、性格（MBTI可作参考）、背景故事、核心欲望、恐惧、口头禅、能力和弱点。
  4. **时间线 (Timeline)：**  历史大事件、故事开始前的重要节点、故事期间的关键事件规划。

**层级二：情节大纲 (The "Blueprint" Layer / The Plot Outline)**   
这是小说的“功能模块规划”。你需要设计出故事的主干，即“用户（读者）体验路径”。

- **核心任务拆解：**
  1. **故事核心：**  一句话概括故事（Logline）。例如：“一个被流放的王子必须联合宿敌，才能从异次元的威胁中拯救他的王国。”
  2. **结构框架：**  采用经典叙事结构，如“三幕剧”、“英雄之旅”或“节拍表 (Beat Sheet)”。
     - *子任务示例：*  使用“英雄之旅”框架，列出主角将经历的12个阶段，并为每个阶段构思关键事件。
  3. **分幕/分卷大纲：**  将故事划分为几个大的部分，并明确每部分的起止点和核心目标。
  4. **章节大纲 (Chapter-by-Chapter Outline)：**  这是最关键的一步。将每一章的目标、关键场景、视角人物（POV）、情节转折点都写下来。

**层级三：场景构建 (The "Scene" Layer / The Building Blocks)**   
这是具体的“代码实现”阶段。每一章由若干个场景组成。

- **核心任务拆解：**
  1. **场景目标：**  这个场景要推动什么情节？揭示什么信息？塑造什么人物关系？
  2. **场景元素：**  时间、地点、在场人物、核心冲突/互动。
  3. **感官细节：**  视觉、听觉、嗅觉、触觉、味觉的描绘。
  4. **对话设计：**  对话不仅要推动情节，还要体现人物性格和潜台词。
  5. **节奏与情绪：**  场景是紧张、悬疑，还是温馨、悲伤？

**层级四：文本生成与润色 (The "Polishing" Layer / The Code Refinement)**   
这是最后的“代码优化”和“UI美化”。

- **核心任务拆解：**
  1. **段落生成：**  根据场景设计，生成具体的描述、对话和心理活动。
  2. **风格统一：**  确保叙事口吻、用词风格符合设定。
  3. **修辞与表达：**  使用比喻、象征等手法，提升文学性。
  4.  **“秀”而非“说” (Show, Don't Tell)：**  将抽象的描述（如“他很愤怒”）转化为具体的行动和细节（如“他指节捏得发白，太阳穴青筋暴起”）。

### 第二部分：提示词使用技巧——与AI高效沟通的艺术

好的提示词，是给AI程序员下达的清晰、无歧义的“开发文档”。

1. **角色扮演法 (Role-Play Priming):**
   - **技巧：**  在所有任务开始前，先给AI一个明确的身份。这是“元指令”，能极大提高输出质量。
   - **示例：**  `你现在是一位获得过雨果奖的科幻小说家，精通硬科幻设定和深刻的哲学思辨。你的写作风格冷静、克制，但充满细节和张力，类似特德·姜。接下来，你将协助我完成一部小说的创作。`
2. **结构化输入法 (Structured Input / The "JSON" for Prompts):**
   - **技巧：**  不要用大段的自然语言描述。使用Markdown、列表、甚至伪代码/JSON格式提供背景信息。模型对结构化数据更敏感。
   - **示例（用于生成角色）：**
     ```markdown
     # 角色创建请求

     ## 基本设定
     - **姓名：** 卡莲
     - **身份：** 银翼城最后的“钟表匠”
     - **世界观：** 一个时间被“时噬虫”吞噬，即将停滞的蒸汽朋克世界。

     ## 核心信息
     - **性格：** 外冷内热，强迫症，对机械和时间有近乎信仰的执着。
     - **目标：** 修复城市中心的“永恒之钟”，逆转时间的消逝。
     - **背景：** 她的师傅在试图修复大钟时被“时噬虫”吞噬，这成为她的心魔。

     ## 写作任务
     请为卡莲写一段出场描写。她正在自己的工作室内，试图修复一个被“时噬虫”轻微侵蚀的怀表。请侧重于描绘她的专注、工作室的环境细节（齿轮、油污、设计图纸），以及通过她的动作和神态，体现出她内心的紧迫感和对逝去师傅的思念。请使用第三人称有限视角。
     ```
3. **上下文注入法 (Context Injection):**
   - **技巧：**  在生成连续内容时，每次都要“喂”给AI必要的“状态信息”。
   - **示例（写完第一章，准备写第二章）：**
     ```
     # 第二章写作任务

     ## 前情提要 (Summary of Chapter 1)
     主角艾拉在黑市上被追捕，最终被一个神秘的独眼老人所救。老人似乎认识她失踪的父亲。艾拉现在正躲在老人的“无名酒馆”的密室里，感到既困惑又警惕。

     ## 本章核心信息 (Current State)
     - **地点：** 无名酒馆的密室，环境昏暗、充满灰尘和旧书的气味。
     - **人物状态：** 艾拉（POV人物）内心充满疑问，对老人不信任但又别无选择。老人则显得高深莫测。
     - **本章目标：** 老人将向艾拉揭示她父亲身份的一小部分秘密，并交给她一个任务作为考验。

     ## 写作指令
     请从艾拉的视角开始描写。她正在打量密室的环境，并思考老人的目的。然后，老人进入密室，两人之间将展开一段充满试探和博弈的对话。请重点刻画艾拉的内心挣扎和老人的压迫感。
     ```
4. **迭代优化法 (Iterative Refinement):**
   - **技巧：**  不要指望一次生成完美结果。将AI的初稿视为草稿，然后通过更具体的指令进行修改。
   - **示例：**
     - **初稿后：**  `很好。但这段对话有点太直接了。请重写这段对话，让老人的话语更隐晦，充满双关和暗示，不要直接说出“考验”这个词，而是通过他的要求来体现。`
     - **细节调整：**  `请在第三段加入更多关于“密室中那幅褪色星图”的细节描写，暗示它与艾拉父亲的过去有关。`

### 第三部分：一次性生成 vs. 分开使用——敏捷开发与瀑布流

这是一个关于“开发模式”的选择题。

- **一次性生成（瀑布流模式）：**
  - **做法：**  编写一个极长、极详细的提示词，包含所有大纲、人物、设定，然后让AI一次性生成一个章节甚至整本书。
  - **优点：**  理论上，如果上下文窗口足够大且模型能力超强，可能在内部逻辑上更连贯。
  - **缺点（致命的）：**
    1. **失控：**  过程是黑箱，你无法中途干预。AI一旦理解错误，整个输出都会偏离。
    2. **上下文限制：**  目前没有任何模型的上下文窗口能容纳一部小说的全部细节。信息在传递过程中会大量丢失和遗忘。
    3. **质量平庸：**  为了兼顾所有方面，AI会倾向于生成“平均化”的、缺乏亮点的文本。
    4. **算力浪费：**  一旦不满意，整个生成过程都需要重来。
- **分开使用（敏捷开发模式）：**
  - **做法：**  严格按照任务拆解的层级，一步一步、一个场景一个场景地生成。每次生成都提供精准的上下文。
  - **优点：**
    1. **高可控性：**  你是导演，每个镜头都在你的掌控之下。可以随时调整方向。
    2. **高质量输出：**  每次任务都聚焦于一个点，AI能投入全部“算力”去打磨细节。
    3. **迭代灵活：**  不满意就重写一小段，成本极低。
    4. **人机协同最大化：**  你负责创意、架构和审美，AI负责繁重的文本填充和灵感激发。

**结论：**  **毫无疑问，分开使用是唯一专业且可行的方法。**  将写作过程看作一系列短小、快速的“开发冲刺 (Sprints)”。

### 第四部分：如何确保前后一致性——项目的“状态管理”

这是长期项目的核心难题，相当于软件开发中的“状态管理”和“版本控制”。

1. **建立“单一信息源” (Single Source of Truth - SSOT):**
   - **工具：**  使用Obsidian, Notion, Scrivener或一个简单的Word/TXT文档。
   - **内容：**  这就是你的 **“世界圣经” (World Bible)** 。它必须包含：
     - **角色表 (Character Sheets)：**  所有角色的详细档案。一旦有更新（如角色学会新技能、失去一只眼睛），立刻记录。
     - **世界观文档：**  魔法/科技规则、地理、历史等。规则一旦设定，不可轻易改变。
     - **时间线：**  记录已发生的所有关键事件及其时间点。
     - **术语表 (Glossary)：**  专有名词、地名、咒语的统一写法和解释。
   - **原则：**  你是这个“数据库”的唯一维护者。AI只负责读取，不负责写入。
2. **“上下文注入”的制度化：**
   - **技巧：**  将“上下文注入法”变成一个固定模板。每次写新场景前，都从你的“世界圣经”中复制粘贴相关信息。
   - **模板示例：**
     ```
     ## 场景写作指令

     ### 1. 全局信息 (Global Context)
     - **小说风格：** [复制你的角色扮演指令]
     - **核心设定：** [复制一两句最关键的世界观设定]

     ### 2. 前情提要 (Immediate Context)
     - **上一场景总结：** [用一两句话总结]

     ### 3. 当前状态 (Current State)
     - **POV人物：** [姓名]
     - **人物状态：** [角色的身体、情绪、心理状态。从角色表中摘录并更新]
     - **环境：** [时间、地点、氛围]

     ### 4. 引用资料 (Reference Data from SSOT)
     - **相关角色档案：** [粘贴在场所有角色的核心档案]
     - **相关世界观规则：** [如果场景涉及特定魔法或技术，粘贴其规则]

     ### 5. 写作任务 (The Task)
     [详细描述本场景的目标和要求]
     ```
3. **人脑作为最终“编译器”和“调试器”：**
   - **职责：**  AI是强大的工具，但它没有真正的“记忆”和“理解”。它只是基于概率在预测下一个词。你，人类作者，是唯一能进行逻辑判断和情感共鸣的角色。
   - **实践：**
     - **定期回顾：**  每写完一章，重读一遍，与你的“世界圣经”进行比对，检查有无矛盾之处。
     - **主动纠错：**  当发现AI生成了与设定矛盾的内容时（比如让一个怕火的角色主动去点篝火），不要直接弃用，可以把它当成一个“Bug Report”。向AI提问：“根据角色设定，他害怕火。请解释为什么他会做出点火的举动，或者修改这个行为，使其更符合人设。” 这有时甚至能激发新的创作灵感（也许他为了救人，克服了恐惧？）。

### 总结

将AI辅助小说创作视为一个 **“人机协同的敏捷开发项目”** ：

1. **你 (架构师)：**  负责顶层设计、任务拆解、制定规范（世界圣经）。
2. **AI (程序员)：**  负责根据你的详细“文档”（提示词）执行具体任务（生成文本）。
3. **流程：**  采用 **“小步快跑、持续集成”** 的策略，分步生成、即时审查、迭代优化。
4. **一致性保障：**  依靠严格的 **“单一信息源”** 和制度化的 **“上下文注入”** 来管理项目状态。

通过这套系统化的方法，你将不再是AI的祈求者，而是它的**指挥官**。你将能够驾驭其强大的生成能力，同时牢牢把控创作的灵魂，最终完成一部真正属于你、同时又闪烁着AI智慧火花的复杂作品。
