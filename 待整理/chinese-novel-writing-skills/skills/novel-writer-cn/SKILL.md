# 中文小说创作总路由

把多阶段小说任务拆给现有专项技能，并维护阶段之间的事实交接。不要把所有写作方法一次性塞进正文上下文。

## 路由优先级

先识别用户此刻要交付的最小成果，只启用必要技能：

| 任务 | 主技能 | 可选复核 |
|---|---|---|
| 新建小说项目 | `story-init` | `plot-structure` |
| 总纲、卷纲、情节线、伏笔 | `plot-structure` | `scene-sequencing` |
| 人物卡、关系、角色状态 | `character-management` | `character-arc` |
| 地点、制度、力量或技术体系 | `worldbuilding` | — |
| 按完整章纲起草章节 | `chapter-drafter` | 由其组织编辑 passes |
| 普通章节、续写或场景 | `chapter-writing` | `scene-sequencing` |
| 中文番茄式网文正文 | `fanqie-webnovel-prose` | `dialogue`、`prose-style` |
| 对话问题 | `dialogue` | — |
| 句子、节奏、用词和声音 | `prose-style` | — |
| 套路与可预测性 | `cliche-transcendence` | — |
| 跨层级长篇修订 | `novel-revision` | 对应专项技能 |
| 中文小说末轮去 AI | 明确调用 `fiction-humanizer-zh` | 不自动调用 |

单项请求直接交给表中主技能。本技能只在跨阶段、跨文件或需要持续交接时保留控制权。

## 项目真值

若用户已有项目结构，沿用原文件名。若没有，只创建当前任务确实需要的文件：

- `story-bible.md`：题材承诺、主题、世界规则、结局方向。
- `outline.md`：总纲、卷纲、当前章纲和待兑现节点。
- `characters.md`：欲望、恐惧、关系、声线、当前状态。
- `continuity.md`：时间、地点、伤势、物品、信息差和伏笔。
- `style-profile.md`：视角、叙述距离、句段节奏、禁区和作者样本。

不要同时维护含义相同的多份文件。动态事实以正文最新已确认事件为准，计划以用户最后确认的大纲为准。

## 多阶段工作流

1. **定边界**：确认当前交付是项目初始化、规划、正文还是修订；不擅自扩大到整本书。
2. **读真值**：只读取本阶段所需项目文件、上一章结尾和用户提供的风格样本。
3. **调用专项层**：按路由表选择一个主技能；只有发现明确问题时才增加复核技能。
4. **交付成果**：先给用户要的正文或文档，不把内部检查过程混入作品。
5. **回写状态**：记录本次真正发生的状态变化、已兑现节点和新增欠账。
6. **阶段验收**：确认因果、角色动机、连续性和读者承诺，再进入下一阶段。

## 交接协议

每次从一个专项层交给下一层，只传递以下内容：

- 本阶段已确认的事实；
- 下一阶段必须保留的约束；
- 未解决但不能擅自决定的问题；
- 用户明确认可或否定的选择。

不要把诊断建议误写成故事事实，不要把候选方案写入人物或世界观真值。

## 修订顺序

按影响范围从大到小处理：

1. 主题承诺、结局和主线因果；
2. 角色动机、关系与信息差；
3. 场景目标、冲突、转折和节奏；
4. 对话声线与潜台词；
5. 句段、用词和重复；
6. 明确点名后才进行去 AI 专项。

上层问题没有解决时，不做大规模句子润色。去 AI 层不得重写情节事实、角色动机或叙事视角。

## 冲突处理

- 用户明确点名的技能优先。
- 窄技能优先于本总路由。
- `fanqie-webnovel-prose` 负责网文正文的生成与章级质量；`fiction-humanizer-zh` 只做成稿末轮清理。
- `better-writing` 负责通用文本；小说正文优先使用小说专项技能。
- 同一轮最多设置一个主写技能，其余只做诊断或复核，避免多套规则互相洗稿。

## 完成标准

- 交付物符合用户当前阶段，而非擅自推进全流程。
- 专名、视角、人物状态和规则一致。
- 每次正文推进都有可描述的因果变化。
- 项目真值已同步，下一次可以从文件而不是记忆继续。
